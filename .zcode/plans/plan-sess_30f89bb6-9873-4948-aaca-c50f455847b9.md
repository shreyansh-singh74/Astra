# Astra — Complete Platform Implementation Plan

## Goal
Turn Astra into a fully functional plagiarism console: **SQLite-persisted**, **multi-language (C++/Python/Java)**, **single + bulk scans with student↔student collusion clustering**, **OpenRouter-powered "fetch AI answers"** (generate reference solutions with 2–3 switchable models), and a **structured multi-page UI** where every option is wired up.

## New dependencies
- Backend: `tree-sitter-python`, `tree-sitter-java` (small wheels), `httpx` (already installed).
- Frontend: none.

---

## Phase 1 — Persistence & API restructure (backend)

**DB layer** — `backend/app/db.py` using stdlib `sqlite3` (py-3.14-safe, zero new deps), WAL mode. Schema:
- `assignments(id, name, description, problem_statement, created_at)`
- `references(id, assignment_id, model_key, model_name, source 'seed'|'manual'|'openrouter', language, code, created_at)`
- `submissions(id, assignment_id, student_name, filename, language, code, created_at)`
- `reports(id, submission_id, assignment_id, mode, verdict_json, max_score, is_flagged, created_at)`
- `collusion_reports(id, assignment_id, matrix_json, clusters_json, created_at)`
- `settings(key PRIMARY KEY, value)` — OpenRouter key, tier weights, thresholds

`app/seed.py`: on first startup, migrate existing `storage/assignments/assignment_1` + ai_vault into the DB so current demo data keeps working.

**Routers** (split monolithic `main.py`): `routers/assignments.py`, `routers/submissions.py`, `routers/vault.py`, `routers/analysis.py`, `routers/openrouter.py`, `routers/settings.py`. Legacy `POST /api/compare` (raw text quick-scan) stays working.

## Phase 2 — Multi-language core + scoring fix

- `app/core/languages.py`: registry mapping `cpp | python | java` → tree-sitter Language, comment/identifier node types, per-language **whitelist** (Python builtins, Java stdlib names), file extensions, Monaco language id.
- Generalize `winnowing.py`, `ast_normalizer.py`, `cfg_compiler.py` to take a `language` param; add CFG node-type handlers (Python `elif_clause`, `try_statement`; Java `do_statement`, `switch_statement`, …).
- `engine.analyze_submission(..., language="cpp")`.
- **Bug fix:** vault comparison currently falls back to raw CodeBERT cosine (saturates ≈1.0, flags independent work). Wire `compute_corpus_semantics()` (already written, never called) into the comparison loop and make fusion weights configurable from settings.

## Phase 3 — OpenRouter "fetch online answers"

- `app/core/openrouter_client.py` (httpx, `https://openrouter.ai/api/v1/chat/completions`):
  - curated model catalog (`openai/gpt-4o`, `anthropic/claude-3.5-sonnet`, `google/gemini-flash-1.5`, `deepseek/deepseek-chat`, …) + live model list fetch
  - `generate_solution(problem_statement, language, model, variant)` — prompts for idiomatic, stylistically distinct solutions; strips markdown fences; validates it parses with the language's tree-sitter grammar before storing.
- Endpoints: `GET /api/openrouter/status`, `POST /api/openrouter/key` (store + test), `GET /api/openrouter/models`, `POST /api/assignments/{id}/vault/generate` (model slugs[] → generated refs stored with `source='openrouter'`, previewed in UI). Vault becomes dynamic — any models, any count. Missing-key state handled gracefully everywhere.

## Phase 4 — Bulk + collusion engine

- `app/core/collusion.py`: precompute per submission (fingerprints, normalized AST, CFG, **one** CodeBERT embedding), then O(N²) pairwise reusing precomputed artifacts; corpus-centered semantics across all submissions; flag pairs above collusion threshold; **union-find clustering** → collusion groups.
- `app/jobs.py`: in-memory job manager + ThreadPoolExecutor (CodeBERT bulk scans exceed HTTP timeouts). `POST /api/analyze/bulk` → `job_id`; `GET /api/jobs/{id}` → progress %, partial results.
- Endpoints: `POST /api/assignments/{id}/submissions` (multi-file **and .zip** upload, student name from filename, language from extension), `GET/DELETE submissions`, `POST /api/analyze/single`, `GET /api/reports/{id}`, report history, `GET /api/reports/{id}/export.csv`.

## Phase 5 — Frontend restructure (Next.js App Router)

- `lib/api.ts` (typed client; base URL from `NEXT_PUBLIC_API_URL`, default `http://localhost:8000` — kills hardcoded URLs) + `lib/types.ts`.
- Navbar gets real navigation: **Scan · Bulk · Assignments · Settings**.
- **`/` Scan** (existing polished flow): dropzone + new paste-code option + language selector; demo presets; results/inspector unchanged (Monaco language now follows submission language). Delete unused legacy `SplitView.tsx` / `CfgVisualizer.tsx`.
- **`/bulk`**: multi-file/zip upload panel → submission table → run scan with progress bar (job polling) → sortable per-student results (max vault score, verdict chips) → **collusion heatmap matrix + cluster cards** ("these 4 students cluster together") → CSV export → row click opens existing inspector drill-down.
- **`/assignments`**: create/edit/delete assignments (name, problem statement, language); per-assignment **vault manager** (browse/delete refs, upload manual reference, and the **"Fetch AI answers"** panel: pick 2–3 OpenRouter models → generate → preview → added to vault).
- **`/settings`**: OpenRouter API key + test button, default generation models, editable tier weight sliders (must sum to 100%), sieve threshold, force-scan, collusion threshold.
- All new components follow the existing dark forensic design system (`globals.css` vars).

## Phase 6 — Tests, docs, verification

- pytest: language registry & per-language tiers, collusion clustering (synthetic submissions), DB layer, OpenRouter client via `httpx.MockTransport`, bulk job flow (CodeBERT monkeypatched for speed).
- Update `explain.md`/README runbook; final end-to-end pass: seed → create assignment → generate refs → upload bulk → collusion report → inspect → export.

## Delivery order
Phases 1→6 sequentially; backend + tests green after each phase, frontend after Phase 5. Bulk collusion scales fine for classroom sizes (≤ ~200 submissions).

**One thing you'll need to provide:** an OpenRouter API key (free to create at openrouter.ai) when you want to test the "fetch answers" feature — the UI will prompt for it in Settings.
