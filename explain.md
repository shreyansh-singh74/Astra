# Astra: Source Forensic Plagiarism Console

Astra is a professional, developer-first forensic analysis platform used to detect AI-assisted plagiarism and source code obfuscation in programming submissions. It analyzes student submissions against reference solutions generated by popular LLMs (GPT-4o, Claude 3.5, Gemini 1.5, DeepSeek) using a multi-tiered pipeline.

---

## 🧬 How Astra Works (The Multi-Tier Pipeline)

Plagiarism detection tools often fail when code is modified with basic tricks like renaming variables, altering spaces, or switching loops. Astra resolves this by combining lexical, structural, logical, and semantic analyses:

```
┌────────────────────────────────────────────────────────┐
│                  Student C++ Submission                │
└───────────────────────────┬────────────────────────────┘
                            ▼
 ┌──────────────────────────────────────────────────────┐
 │             Tier 1: Token Winnowing Sieve            │  ◄── [Quick Check]
 └──────────────────────────┬───────────────────────────┘
                            │ (If Similarity < 10%)
                            ├──────────────────────────┐
                            │ (Else / Forced)          ▼
                            ▼                     [Safe / Skip]
 ┌──────────────────────────────────────────────────────┐
 │              Tier 2: AST Normalization               │  ◄── [Syntax Tree Check]
 └──────────────────────────┬───────────────────────────┘
                            ▼
 ┌──────────────────────────────────────────────────────┐
 │             Tier 3: Control Flow Graph (CFG)         │  ◄── [Logical Path Check]
 └──────────────────────────┬───────────────────────────┘
                            ▼
 ┌──────────────────────────────────────────────────────┐
 │            Tier 4: CodeBERT Semantic Embed           │  ◄── [Semantic Check]
 └──────────────────────────┬───────────────────────────┘
                            ▼
 ┌──────────────────────────────────────────────────────┐
 │                  Multi-Tier Fusion                   │  ◄── [Score Combination]
 └──────────────────────────────────────────────────────┘
```

## 🔍 Detail by Tier

### 1. Token Winnowing (Lexical Tier)
* **What it is:** Measures literal text overlap while ignoring layout details.
* **How it works:**
  1. **Lexical Scrubbing:** Astra uses a C++ parser (`tree-sitter`) to traverse the code and completely remove all comment nodes (e.g. `// line` or `/* block */`).
  2. **K-Grams:** The remaining code string is split into overlapping sequences of length $K=20$.
  3. **MD5 Hashing:** Each K-gram is hashed into a numerical value.
  4. **Winnowing Algorithm:** A sliding window of size $W=10$ selects the minimum hash value of each window. This subset of hashes forms the code's **fingerprint**.
  5. **Jaccard Similarity:** Compares the fingerprint hash sets of the student code and reference code.
* **The Sieve Effect:** If the similarity score is below the threshold (default: 10%), the pipeline flags the code as "Safe" and skips the expensive remaining stages (unless "Bypass Sieve" is active).

### 2. AST Normalization (Structural Tier)
* **What it is:** Exposes plagiarism disguised by renaming variables or custom functions.
* **How it works:**
  1. Astra parses the code into an **Abstract Syntax Tree (AST)**.
  2. It identifies custom variable identifiers and function names.
  3. It replaces them sequentially with standard tags: `var_0`, `var_1`, `func_0`, etc.
  4. **Whitelist protection:** Standard C++ keywords and libraries (e.g., `int`, `std`, `vector`, `main`, `abs`) are kept intact so that the program structure is not destroyed.
  5. It runs token winnowing on the normalized AST code to calculate the structural overlap score.

### 3. Control Flow Graph (CFG) Compiler (Logical Tier)
* **What it is:** Analyzes the logical execution paths of the code (loops, branches, entry/exit points).
* **How it works:**
  1. The compiler parses conditional statements (`if`), loops (`for`, `while`), control switches (`break`, `continue`), and functions into nodes and directed edges.
  2. It evaluates graph similarity using the **Weisfeiler-Lehman Graph Isomorphism Kernel** (which hashes graph colors to check structural equivalence).
  3. If graph structures match perfectly (isomorphic), it returns a score of `1.0`. Otherwise, it falls back to comparing node type distributions and edge ratios.

### 4. CodeBERT Semantic Vector (Semantic Tier)
* **What it is:** Uses a deep neural network to understand *what* the code actually does conceptually, bypassing syntactic obfuscation (like rewriting loops using arrays).
* **How it works:**
  1. Feeds the scrubbed C++ code to the pre-trained **CodeBERT** model (`microsoft/codebert-base`).
  2. Extracts a 768-dimensional semantic embedding vector.
  3. Computes the **Cosine Similarity** between the student code embedding and the reference code embedding.

## 📊 Score Fusion & AI Detection Rules

Astra combines the scores from the four tiers using a weighted formula:
$$\text{Fused Score} = 20\% \times \text{Token} + 20\% \times \text{AST} + 20\% \times \text{CFG} + 40\% \times \text{Semantic}$$

If these scores match specific thresholds, the engine diagnoses the plagiarism signature:
* **GPT-4o / Gemini 1.5 Pattern:** Low token overlap, but high AST structure and semantic similarity (indicates variable renaming and whitespace editing).
* **Claude 3.5 Pattern:** Low token and AST overlap (indicates advanced struct/array de-clustering), but very high semantic correlation.
* **Flat Logic Duplication:** High AST and semantic scores with standard loop structures (indicates copy-pasted control blocks).

```bash
PYTHONPATH=.. uvicorn app.main:app --reload
```

```bash
cd frontend
npm run dev
```
