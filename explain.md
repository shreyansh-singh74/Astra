# Astra: Source Forensic Plagiarism Console

Astra is a professional, developer-first forensic analysis platform used to detect AI-assisted plagiarism and source code obfuscation in programming submissions. It analyzes student submissions against reference solutions generated by popular LLMs (GPT-4o, Claude 3.5, Gemini 1.5, DeepSeek) using a multi-tiered pipeline.

Supports **C++ / Python / Java** (tree-sitter grammars), SQLite persistence, single + bulk scans with student↔student collusion clustering, and OpenRouter-powered "fetch AI answers".

---

## 🧬 How Astra Works (The Multi-Tier Pipeline)

Plagiarism detection tools often fail when code is modified with basic tricks like renaming variables, altering spaces, or switching loops. Astra resolves this by combining lexical, structural, logical, and semantic analyses:

```
┌────────────────────────────────────────────────────────┐
│                  Student Submission                    │
│              (C++ · Python · Java)                     │
└───────────────────────────┬────────────────────────────┘
                             ▼
 ┌──────────────────────────────────────────────────────┐
 │             Tier 1: Token Winnowing Sieve            │  ◄── [Quick Check]
 └──────────────────────────┬───────────────────────────┘
                             │ (If Similarity < 10%)
                             ├──────────────────────────┐
                             │ (Else / Forced)          ▼
                             ▼                     [Safe / Skip]
 ┌──────────────────────────────────────────────────────┐
 │              Tier 2: AST Normalization               │  ◄── [Syntax Tree Check]
 └──────────────────────────┬───────────────────────────┘
                             ▼
 ┌──────────────────────────────────────────────────────┐
 │             Tier 3: Control Flow Graph (CFG)         │  ◄── [Logical Path Check]
 └──────────────────────────┬───────────────────────────┘
                             ▼
 ┌──────────────────────────────────────────────────────┐
 │            Tier 4: CodeBERT Semantic Embed           │  ◄── [Semantic Check]
 └──────────────────────────┬───────────────────────────┘
                             ▼
 ┌──────────────────────────────────────────────────────┐
 │                  Multi-Tier Fusion                   │  ◄── [Score Combination]
 └──────────────────────────────────────────────────────┘
```

## 🔍 Detail by Tier

### 1. Token Winnowing (Lexical Tier)
* **What it is:** Measures literal text overlap while ignoring layout details.
* **How it works:**
  1. **Lexical Scrubbing:** tree-sitter parses the code (per-language comment nodes: `comment` for C++/Python, `line_comment`/`block_comment` for Java) and removes comments.
  2. **K-Grams:** The remaining code string is split into overlapping sequences of length $K=20$.
  3. **MD5 Hashing:** Each K-gram is hashed into a numerical value.
  4. **Winnowing Algorithm:** A sliding window of size $W=10$ selects the minimum hash value of each window. This subset of hashes forms the code's **fingerprint**.
  5. **Jaccard Similarity:** Compares the fingerprint hash sets of the student code and reference code.
* **The Sieve Effect:** If the similarity score is below the threshold (default: 10%, configurable in Settings), the pipeline flags the code as "Safe" and skips the expensive remaining stages (unless "Bypass Sieve" is active).

### 2. AST Normalization (Structural Tier)
* **What it is:** Exposes plagiarism disguised by renaming variables or custom functions.
* **How it works:**
  1. Parses the code into an **Abstract Syntax Tree (AST)** with the language's tree-sitter grammar.
  2. Identifies custom variable identifiers and function names (C++ `function_declarator`, Python `function_definition`/`class_definition` name field, Java `method_declaration`/`class_declaration` name field).
  3. Replaces them sequentially with standard tags: `var_0`, `var_1`, `func_0`, etc.
  4. **Whitelist protection:** Per-language whitelists (C++ STL keywords, Python builtins, Java stdlib names) are kept intact so program structure is not destroyed.
  5. Runs token winnowing on the normalized AST code to calculate the structural overlap score.

### 3. Control Flow Graph (CFG) Compiler (Logical Tier)
* **What it is:** Analyzes the logical execution paths of the code (loops, branches, entry/exit points).
* **How it works:**
  1. Compiles conditionals (`if`, Python `elif_clause`), loops (`for`, `while`, Java `do_statement`), `switch`/`switch_expression`, `try`/`catch`/`finally`/`except`, `break`, `continue`, `return`, and functions into nodes and directed edges.
  2. Evaluates graph similarity using the **Weisfeiler-Lehman Graph Isomorphism Kernel** (hashes graph colors to check structural equivalence).
  3. If graph structures match perfectly (isomorphic), returns `1.0`. Otherwise falls back to node-type distribution + edge-ratio similarity.

### 4. CodeBERT Semantic Vector (Semantic Tier)
* **What it is:** Uses a deep neural network to understand *what* the code actually does conceptually, bypassing syntactic obfuscation.
* **How it works:**
  1. Feeds scrubbed code to the pre-trained **CodeBERT** model (`microsoft/codebert-base`).
  2. Extracts a 768-dimensional semantic embedding vector.
  3. Computes similarity with **corpus-centered cosine** (`compute_corpus_semantics`): subtracts the mean embedding of student + all same-language references before cosine. Raw cosine saturates near 1.0 for any code solving the same assignment (shared boilerplate dominates); centering removes the shared component so independent solutions score near 0 while renamed copies keep 0.45–0.85.

## 📊 Score Fusion & AI Detection Rules

Astra combines the four tiers using configurable weights (default):

$$\text{Fused Score} = 20\% \times \text{Token} + 20\% \times \text{AST} + 20\% \times \text{CFG} + 40\% \times \text{Semantic}$$

Weights are editable in **Settings** (must sum to 100%) and applied to every comparison. Diagnostics:

* **GPT-4o / Gemini 1.5 Pattern:** Low token overlap, but high AST structure and semantic similarity (variable renaming + whitespace editing).
* **Claude 3.5 Pattern:** Low token and AST overlap (structural de-clustering), but high semantic correlation.
* **Flat Logic Duplication:** High AST and semantic scores with standard loop structures (copy-pasted control blocks).
* **High Plagiarism Risk:** Fused score ≥ 0.70.

Collusion (student↔student) reuses the same tiers pairwise: precomputed fingerprints/AST/CFG/embeddings, corpus-centered semantics across all submissions, union-find clustering above the collusion threshold (default 0.60).

## 💻 Running the Platform

### Start Backend (FastAPI on Port 8000)
```bash
cd backend
source .venv/bin/activate
PYTHONPATH=.. uvicorn app.main:app --reload
```

### Start Frontend (Next.js on Port 3000)
```bash
cd frontend
npm run dev
# optional: NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev
```

First backend startup seeds SQLite (`backend/astra.db`, WAL mode) from `storage/assignments/assignment_1/ai_vault/*.cpp` so the demo keeps working.

### Run backend tests
```bash
cd backend
source .venv/bin/activate
python -m pytest tests/ -q --ignore=tests/test_api_flow.py   # fast (CodeBERT mocked)
python -m pytest tests/test_api_flow.py -q                    # full pipeline incl. real CodeBERT + bulk/collusion (~60s)
```

## 🖥️ UI Map (Next.js App Router)

* **Scan (`/`)** — quick forensic scan: assignment picker, C++/Python/Java selector, file dropzone, paste-code box, demo presets; vault similarity cards + Code/CFG/Debug inspector (Monaco follows submission language). Quick path uses `POST /api/compare`.
* **Bulk (`/bulk`)** — classroom workflow: multi-file/`.zip` upload → submission table → `POST /api/analyze/bulk` background job with progress polling (`GET /api/jobs/{id}`) → sortable per-student vault scores → student↔student heatmap + cluster cards ("these 4 students cluster together") → CSV exports → row click drills into the Scan inspector.
* **Assignments (`/assignments`)** — create/edit/delete assignments; per-assignment vault manager (browse/delete, manual upload with language); **Fetch AI answers** panel: pick 2–3 OpenRouter models → generate → preview → stored with `source='openrouter'`.
* **Settings (`/settings`)** — OpenRouter API key + test button, default generation models, tier weight sliders (must sum to 100%), sieve threshold, collusion threshold.

API base URL comes from `NEXT_PUBLIC_API_URL` (default `http://localhost:8000`) — no hardcoded URLs.

## 🔑 OpenRouter ("fetch AI answers")

You need your own key (free at openrouter.ai) to test generation. Add it in **Settings**:
* `GET /api/openrouter/status`, `POST /api/openrouter/key` (validates via `GET /key`), `GET /api/openrouter/models` (curated catalog + live list), `POST /api/openrouter/assignments/{id}/vault/generate` (also aliased at `POST /api/assignments/{id}/vault/generate`).
* Generation prompts request one self-contained file in distinct styles, strips markdown fences, and rejects output that fails tree-sitter parsing. Missing-key state is handled gracefully in the UI.

## 📦 Key API Endpoints

* Assignments: `GET/POST /api/assignments`, `GET/PUT/DELETE /api/assignments/{id}`
* Vault: `POST /api/assignments/{id}/vault`, `DELETE /api/vault/{ref_id}`
* Submissions: `POST /api/assignments/{id}/submissions` (multi-file + `.zip`), `GET /api/assignments/{id}/submissions`, `GET/DELETE /api/submissions/{id}`
* Analysis: `POST /api/analyze/single`, `POST /api/analyze/bulk` → `job_id`, `GET /api/jobs/{id}`, legacy `POST /api/compare`
* Reports: `GET /api/reports/{id}`, `GET /api/assignments/{id}/reports`, `GET /api/reports/{id}/export` (CSV), collusion `GET /api/collusion/{id}` + `/export`
* Settings: `GET/PUT /api/settings`
